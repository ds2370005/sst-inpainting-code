# Adversarial physical model loss：平原論文の2段階ネットワークへの適用

参照論文：Hiraharaら、*Denoising and Inpainting of Sea Surface Temperature Image with Adversarial Physical Model Loss*、ACPR 2019／LNCS 2020。
DOI：10.1007/978-3-030-41404-7_24。損失関数の根拠は第3.1節の式（3）〜（9）。

## 実装した目的関数

以下では、生成器をG、識別器をDとする。全体・局所の各識別器は、確率に変換する前の値である**ロジット（logits）**を出力する。実装では数値的に安定した `logsigmoid` を用い、論文の対数確率を計算する。

- 各識別器の目的関数：`V_b = mean(log sigmoid(real_b)) + mean(log sigmoid(-fake_b))`。
- 全体・局所の合成：`V = beta * V_global + (1-beta) * V_local`。
- Dは `-(1-alpha) * V` を最小化する。この更新ではGの出力を計算グラフから切り離す。
- Gは `alpha * L_rec + (1-alpha) * L_adv_G` を最小化する。
- Gの敵対的損失：`L_adv_G = beta * mean(log sigmoid(-fake_global)) + (1-beta) * mean(log sigmoid(-fake_local))`。
- 実データ側の項はGに対する勾配を持たないため、Gの更新から省略する。
- 局所損失はパッチ位置とバッチの両方について平均する。ロジットを先に平均してから対数確率を計算する処理ではない。全体損失はバッチについて平均する。
- 再構成損失は式（6）の `L_rec = mean_batch(norm_2((prediction-target)*observed_mask))`。画像ごとのマスク付きL2ノルムを平均する。**L2ノルムの二乗、画素平均MSE、RMSEとは異なる。** 正解側の欠損値NaNは計算から除外し、全画素欠損や誤差ゼロの場合も勾配が有限のゼロになるようにする。

`beta=0.5` は、参照論文の第4節における全体・局所識別器を併用する実験に合わせた設定である。一方、`alpha=0.99` は**今回の実装で設定した調整用の初期値**であり、論文に明記された数値ではない。論文には取り得る範囲が示されている。

マスク付きMSEからL2ノルムへの変更によって損失の大きさが変わるため、従来の損失値やハイパーパラメータとは直接比較できない。Dの損失にも式（9）の係数 `1-alpha` を掛けるため、ログに出るDの損失値の大きさも変わる。従来の非常に小さいDの学習率 `1e-8` は既存のTGRS再現実装の設定として維持しているため、Dが十分に学習できるかを検証する必要がある。

論文のminimax形式では、Gの敵対的損失が負になることは正常である。これは非飽和型の `-log D(fake)` とは異なる。minimax形式では勾配が飽和する可能性があり、数式を実装することだけでGANの安定性や物理的な正確さが保証されるわけではない。

## 既存の2段階ネットワークへの適用方法

| 項目 | 実装内容 |
|---|---|
| 生成器・入力 | 既存のTGRS再現実装の256×256・9フレームによる平均推定／偏差推定構成を維持 |
| 全体識別器 | 既存のTGRS論文Table IIIに対応する、単一の判定値を出す識別器 |
| 局所識別器 | 畳み込み型PatchGANを追加。256×256入力に対し32×32のロジットを出力。ACPR論文Fig. 8の構造をそのまま複製したものではない |
| 平均推定の再構成損失 | 既存の「学習の進行に伴い重みが減る月平均項＋週平均項」を維持し、それぞれをマスク付きL2に変更 |
| 平均推定の生成側／実データ側 | 推定週平均SST／シミュレーションの週平均SST |
| 偏差推定の生成側／実データ側 | 凍結した平均推定器の出力＋SSTスケールに換算した推定偏差／毎時シミュレーションSST |
| 雲マスクによる拡張 | 別の衛星画像から取得した雲マスクを使用する既存処理を維持。再構成損失には元の観測有効マスクを使用 |
| サンプリング | シミュレーション側は衛星側の日時・位置と独立に選択。対応する正解画像としてMSEを計算する用途には使わない |

添付されたACPR論文は64×64・3日分の時空間ボリュームと過去のデータ同化画像を使用しており、TGRS論文の256×256・9フレームとは構成が異なる。今回は**ACPR論文の損失関数の考え方を、既存のTGRS再現実装へ適用**している。ACPR論文全体の完全再現を意味しない。また、偏微分方程式の残差による制約は追加しておらず、物理量の保存を保証するものでもない。

## 毎時シミュレーションデータの入力

標準の `config.yaml` は `data.assimilation_mode: hourly` に設定している。毎時データの指定がない場合はエラーにし、日平均GPVを自動的に代用しない。この設定項目がない古い設定ファイルは従来の動作を維持する。従来の日平均データを使った比較実験では、明示的に `legacy_gpv` を指定する。

実データのダウンロードや読み出し確認はまだ行っていない。JCOPE-T 1ksの変数名・鉛直座標・欠損値・時刻の意味は、実際に提供されたファイルで確認する必要がある。

入力変換処理で、先に**衛星画像と同じ座標・並び順の格子上にある、単位℃のSST**を用意する。

```text
aligned_simulation/
  lat.npy                       # 統合衛星データと同じ緯度座標・並び順
  lon.npy                       # 統合衛星データと同じ経度座標・並び順
  simulation.json
  frames/20240801T000000/sst.npy  # [緯度, 経度]。陸域・欠損はNaN
  frames/20240801T010000/sst.npy
  ...
```

`simulation.json` の記述例を以下に示す。実際には、対象となる全フレームを列挙する必要がある。

```json
{
  "units": "degC", "cadence_hours": 1, "time_basis": "UTC",
  "frames": [
    {"time": "2024-08-01T00:00:00Z", "path": "frames/20240801T000000"},
    {"time": "2024-08-01T01:00:00Z", "path": "frames/20240801T010000"}
  ]
}
```

次のコマンドで、独立したシミュレーション学習用プールを作成する。週平均の作成には少なくとも168時間連続したデータが必要となる。`/path/to/` は実際の保存先に置き換える。

```bash
python3 -m src.preprocessing.hourly_assimilation \
  --source /path/to/aligned_simulation \
  --satellite-root /workspace/sst-inpainting-code/data/unified_sst \
  --output /path/to/physical_hourly_pool
```

処理ではメモリマップを使ってフレームを順に読み、移動窓内の合計を更新する。毎時と週平均の全域データを保存するため、追加のディスク容量が必要になる。パッチは全画素が有限値である256×256の領域から選ぶ。

週平均には、**記録された時刻を最後の標本とする、連続168個の毎時データ**を用いる。どれか1標本でも欠損している画素は、その週平均でも欠損とする。この集計方法は今回の実装で定めたものであり、添付論文に記載された数式ではない。衛星側の「7日分の同時刻データ」から週平均を作る既存処理は変更していない。

時刻の欠落がある場合は移動窓をリセットする。時間補間や日平均値の毎時への複製は行わない。ただし、日平均データを誤って毎時と記載した場合、メタデータだけではその誤りを判別できない。入力変換時に元製品の時間的な意味を正しく保持する必要がある。

既存の衛星データと新しいシミュレーション用プールを使う学習コマンドは以下のとおり。

```bash
python3 main.py \
  --data-root /workspace/sst-inpainting-code/data/unified_sst \
  --assimilation-root /path/to/physical_hourly_pool \
  --run-dir /workspace/sst-inpainting-code/outputs/physical_hourly_001 \
  --epochs 10 --batch-size 32 --num-workers 0 --stop-after anomaly
```

`--assimilation-root` には、未変換のJCOPE NetCDFや従来の日平均GPV出力を指定しない。今回の準備処理は、既存のGPV tarファイル用前処理とは別の処理である。

両学習段階で識別器の構造が変わるため、新しい実験として学習を開始する。生成器の構造は変更していないが、過去のチェックポイントは今回の目的関数で学習した結果ではない。チェックポイントには損失設定と目的関数名を保存する。

実装時にサーバーでの学習やリモートからのダウンロードは実行していない。
